# Glamour

CRM для салона красоты с записью через VK. Клиент выбирает услугу, мастера и время в переписке с сообществом, а администратор работает с расписанием и заявками в веб-панели.

Бот и панель используют одну базу и общую логику бронирования. Услуга определяет длительность визита, расписание — доступные часы мастера, а существующие записи исключают занятые интервалы.

## Что есть в проекте

- Запись через VK с сохранением состояния диалога.
- Клиенты, категории услуг, цены и длительность процедур.
- Мастера, их услуги и рабочее расписание.
- Создание, перенос и отмена записей, изменение статусов посещения.
- Подтверждения и напоминания за 24 часа и за 2 часа до визита.
- Веб-панель администратора, сводная статистика и журнал действий.
- API с документацией Swagger и тесты основных сценариев.

## Стек и устройство

Backend написан на Python 3.11 с FastAPI, SQLAlchemy 2 и Pydantic. В Docker используется PostgreSQL 16; для локальной работы без Docker предусмотрена SQLite. Панель администратора — React, TypeScript и Vite.

```text
backend/app/api/       маршруты API и проверки доступа
backend/app/models/    модели SQLAlchemy
backend/app/schemas/   входные и выходные данные
backend/app/services/  бронирование, уведомления и VK-диалоги
backend/app/scripts/   демо-данные и обработка уведомлений
backend/tests/         тесты
frontend/src/          веб-панель
deploy/                конфигурации развёртывания
docs/                  описание архитектуры и запуска на сервере
```

После сборки панель обслуживается самим FastAPI по адресу `/admin`. Это позволяет запустить демонстрацию одним приложением.

## Быстрый запуск через Docker

Понадобится Docker с Compose. Для просмотра панели подключение VK не требуется.

```bash
git clone https://github.com/Aoruszy/glamour-vk-bot.git
cd glamour-vk-bot
docker compose up --build -d
docker compose exec app python -m app.scripts.seed_demo --with-clients --with-appointments
```

Последняя команда добавляет услуги, мастеров, расписание, демонстрационных клиентов и записи.

После запуска доступны:

| Адрес | Что открывается |
| --- | --- |
| [localhost:8000/admin/](http://localhost:8000/admin/) | Панель администратора |
| [localhost:8000/docs](http://localhost:8000/docs) | Документация API |
| [localhost:8000/healthz](http://localhost:8000/healthz) | Проверка доступности приложения |

Демо-вход: `admin` / `glamour-admin`. PostgreSQL занимает порт `5432`, приложение — `8000`.

Compose содержит локальные пароли и секреты для демонстрации. Перед внешним развёртыванием их нужно заменить. Таблицы создаются при старте backend; управление изменениями схемы через миграции пока не настроено.

Посмотреть логи и остановить приложение:

```bash
docker compose logs -f app
docker compose down
```

Остановка сохраняет базу в Docker volume. У скрипта заполнения есть флаг `--reset`: он очищает данные, поэтому использовать его следует только на демонстрационной базе.

## Запуск без Docker

Понадобятся Python 3.11 и Node.js 24. Из корня проекта создайте окружение, установите backend и соберите панель:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e './backend[dev]'
cd frontend
npm ci
npm run build
cd ../backend
python -m app.scripts.seed_demo --with-clients --with-appointments
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

Без `DATABASE_URL` backend использует SQLite: файл `glamour.db` появится в каталоге `backend`. Панель и API доступны по тем же путям, что и при запуске через Docker.

При таком запуске файл `.env`, если он нужен, размещается в `backend`, откуда запускается процесс. В Docker настройки приложения берутся из секции `environment` в Compose.

## Подключение VK

Для работы с сообществом нужны `VK_ACCESS_TOKEN`, `VK_CALLBACK_SECRET`, `VK_CONFIRMATION_TOKEN` и `VK_GROUP_ID`. Их описание и значения по умолчанию находятся в `backend/app/config.py`.

В настройках Callback API укажите адрес `https://ваш-домен/api/v1/vk/events`, тот же секрет и строку подтверждения, которые заданы в приложении. Для Docker эти переменные нужно передать контейнеру `app`: файл `.env` сам по себе не добавляет их в его окружение.

С параметрами из локального Compose можно изучать панель и API без отправки сообщений в VK. Для настоящих ответов и напоминаний нужен токен сообщества.

## Тесты

После установки зависимостей backend с группой `dev`, из каталога `backend`:

```bash
python -m pytest -q
```

Тесты проверяют авторизацию, обработку VK-событий, расписания, занятые и прошедшие интервалы, перенос и отмену записей, а также время отправки напоминаний. Для тестов создаётся отдельная SQLite-база во временном каталоге.

## Что ещё нужно доработать

Проверка пересечений записей сейчас выполняется в сервисном слое. Для одновременных бронирований нужна дополнительная защита на уровне БД и тесты конкурентных запросов.

Уведомления обрабатываются фоновым потоком внутри приложения. При запуске нескольких процессов нужно отдельно решить, кто забирает задания и как исключается повторная отправка. В дальнейшем эту работу можно вынести в отдельный обработчик.

На frontend основная часть интерфейса пока сосредоточена в `App.tsx`; его стоит разделить по разделам панели.

Подробности: [архитектура](docs/architecture.md), [развёртывание на сервере](docs/deployment.md), [размещение на общем Ubuntu-сервере](docs/deployment-ubuntu-shared.md). В инструкции развёртывания упоминается `.env.production.example`, но в текущем репозитории этого файла нет — настройки окружения потребуется подготовить самостоятельно.
